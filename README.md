# cwayn

Personal experiment: running Qwen3-0.6B from plain C on the CPU.
The engine is `src/runq.c`, derived from qwen3.c. Roadmap and status: [TODO.md](TODO.md).

## Quick start

```sh
scripts/download_models.py            # Qwen/Qwen3-0.6B (bf16) + Q4_K_M GGUF, pinned + checksummed
scripts/setup_venv.sh                 # .venv with CPU torch, for the exporter only
scripts/export_q8.sh                  # -> models/Qwen3-0.6B-q8.bin (Q8_0, ~630 MB)
# (or: make models, which runs download + export if the .bin is missing)
make                                  # -> ./runq  (make debug -> ./runq-debug, make generic -> ./runq-generic)

OMP_NUM_THREADS=8 ./runq models/Qwen3-0.6B-q8.bin -c 4096   # interactive chat
OMP_NUM_THREADS=8 ./runq models/Qwen3-0.6B-q8.bin -c 4096 -t 0 -n 200 -i "Why is the sky blue?"
make test                             # regression suite, ~22 s (tests/README.md)
make bench                            # thread sweep, prefill/decode tok/s (scripts/bench_qwen3c.sh)
make bench-prefill                    # prefill tok/s vs prompt length and -b (scripts/bench_prefill.sh)
scripts/fetch_mynah.sh                # optional reference engine, then scripts/bench_mynah.sh
```

Use `OMP_NUM_THREADS=8` (12 gives ~30% faster prefill and about the same decode; 16 collapses, see
benchmarks below). Always pass `-c` (context size): without it the KV cache is sized for the full
40,960-token context, about 9 GB of address space.

## Models (`scripts/download_models.py --list`)

| set | source | file(s) |
|---|---|---|
| `hf` | `Qwen/Qwen3-0.6B` @ `c1899de` | bf16 safetensors + tokenizer (input for the Q8_0 export) |
| `q4km` | `unsloth/Qwen3-0.6B-GGUF` @ `50968a4` | `Qwen3-0.6B-Q4_K_M.gguf` (imatrix) |
| `q8gguf` | `unsloth/Qwen3-0.6B-GGUF` @ `50968a4` | `Qwen3-0.6B-Q8_0.gguf` |

Revisions are pinned. Each file is verified by sha256 (LFS files) or git blob sha1 (small files).

## Layout and third-party code

- `src/runq.c`: our engine, from qwen3.c's `runq.c` (MIT, see `LICENSE`). Changes so far:
  `-n <int>` max new tokens, plus a `[timing]` line on stderr (prefill and decode tok/s);
  no classifier matmul for prompt tokens whose logits are unused;
  batched prefill (`-b <int>` tokens per chunk, default 64, `-b 1` = token by token):
  `forward_batch()`, bit-identical to the token-by-token path;
  AVX-512 VNNI kernels for the GEMM (prefill) and GEMV (decode) on weights repacked at load
  (`src/kernels_avx512.h`, compile-time selection; `-DRUNQ_GENERIC` / `make generic` or a CPU
  without AVX-512 VNNI gives the generic C kernels, bit-identical results);
  SwiGLU NaN fix (`-Ofast` expf overflow, it did corrupt some last-layer activations);
  a rewritten tokenizer matching HF (added tokens, Qwen2 pre-tokenizer regex, byte-level BPE
  with a hash map and a merge heap; ~1 ms for 2,000 tokens; input assumed NFC);
  test hooks `-m tokenize` and `-m logits -o <file>` (see `tests/README.md`).
- `src/kernels_avx512.h`: the AVX-512 VNNI Q8_0 GEMM / GEMV and the weight repacking (layout
  and bit-identity argument in its header comment).
- `src/unicode_tables.h`: \p{L}/\p{N}/\s ranges for the pre-tokenizer, generated by
  `tools/gen_unicode_tables.py` (Python's unicodedata, Unicode 15.1).
- `third_party/qwen3.c/`: pristine https://github.com/adriancable/qwen3.c @ `55643ff`
  (2025-07-05), kept for diffs (`diff -u third_party/qwen3.c/runq.c src/runq.c`). Only its
  `export.py`/`model.py` are used, by `scripts/export_q8.sh`. qwen3.c itself started from
  Andrej Karpathy's llama2.c.
- `third_party/mynah-slm/`: not committed. `scripts/fetch_mynah.sh` clones
  https://github.com/mynah-org/mynah-slm @ `cde1599` (2026-09-22) and builds it (needs
  `libopenblas-dev`). Reference and benchmarks only.

## Benchmarks

### cwayn `runq` (2026-10-25, Step 3a: AVX-512 VNNI kernels; 16-vCPU EPYC Genoa VM, shared, load 2-10)

Prefill tok/s (`scripts/bench_prefill.sh -l "450 1500" -b "64 128" -t "8 12" -r 2`: chat, greedy,
`-c 4096 -n 16`), previous commit (generic C GEMM) -> now, same session:

| prompt tokens | threads | `-b 64` (default) | `-b 128` | `-b 256` (now) |
|---|---|---|---|---|
| 451 | 8 | 278 -> **1,127** | 287 -> **1,179** | 1,212 |
| 451 | 12 | 382 -> **1,391** | 389 -> **1,559** | 1,648 |
| 1,500 | 8 | 228 -> **518** | 233 -> **541** | 557 |
| 1,500 | 12 | 307 -> **741** | 319 -> **748** | 770 |

Decode tok/s (`scripts/bench_qwen3c.sh`, 256 new tokens, best of 3, old/new interleaved):

| threads | 4 | 8 | 12 |
|---|---|---|---|
| before | 77.4 | 120.9 | 124.7 |
| now | **114.5** | **138.7** | **141.6** |

- GEMM: 0.30 -> 2.42-2.48 TOPS int8 at 8 threads (8x), about 85% of the measured `vpdpbusd`
  peak (2.9 TOPS at 8 threads, 372 GOPS per thread); 3.2 TOPS at 12 threads.
- Decode reads ~0.63 GB of weights (+ ~34 MB of KV cache) per token: 8 threads ~92 GB/s, 4 threads
  ~76 GB/s, i.e. at the measured read bandwidth (today 35 / 72 / 100 / 114 GB/s at 1 / 4 / 8 / 12
  threads; 1 thread: 25 -> 45 tok/s, ~30 GB/s).
- Prefill time now (8 threads, `-b 128`, `-DRUNQ_PROFILE`): 451 tokens: GEMMs 43%, attention 42%,
  rest 15%; 1,500 tokens: GEMMs 19%, attention 74% (fp32, ~126 GFLOPS), rest 7%. See TODO Step 3b.
- Weight repacking at load: +~55 ms startup (0.40 -> 0.45 s), peak RSS 1,316 -> 1,362 MB (the mapped
  Q8_0 pages are released after packing).
- 16 threads still collapse (OpenMP spin barriers under oversubscription, see below).

### qwen3.c and mynah-slm (2026-10-24, before cwayn's changes; greedy, 256 new tokens, best of 3)

Decode tok/s:

| threads | qwen3.c Q8_0 | mynah-slm Q8_0 | mynah-slm Q4_K_M |
|---|---|---|---|
| 1 | 21.5 | 17.3 | 14.3 |
| 4 | 68 | 32.5 | 30.0 |
| 8 | **~100** | 35.5 | 34.4 |
| 12 | ~95 | 34.8 | 34.5 |
| 16 | **~11** (collapse) | 30.3 | 30.4 |

- qwen3.c at 16 threads collapses. This is not VM throttling (0% steal time), but OpenMP
  spin-barrier oversubscription: with every vCPU spinning, any other process preempting one
  thread stalls all of them at every barrier (hundreds per token). `OMP_WAIT_POLICY=passive`
  is worse at every thread count (~20 tok/s). Use 8 threads, which also leaves headroom.
- mynah-slm `--fast` (int8 activations) made no measurable difference here.
- With mynah-slm, Q4_K_M is no faster than Q8_0 on this CPU.
- Greedy Q8_0 output is identical from qwen3.c and mynah-slm (cross-check of both engines).
- Batched prefill (Step 2, generic C GEMM, 8 threads, 451 / 1,500 tokens): 124.8 / 81.4 tok/s token
  by token (`-b 1`) -> 289 / 231 at `-b 64`; details in TODO.md.

## Known limitations of qwen3.c

- Chat mode keeps no history: each user turn restarts at position 0.
- Q8_0 only; there is no GGUF loader.
